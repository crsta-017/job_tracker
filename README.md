# Job Application Tracker (MERN)

## 1. MongoDB Atlas
1. Create a free cluster at https://cloud.mongodb.com.
2. Database Access: add a user with a password.
3. Network Access: add your IP (or 0.0.0.0/0 for testing).
4. Connect > Drivers: copy the connection string.

## 2. Backend
    cd server
    npm install
    cp .env.example .env     # paste your MONGO_URI
    npm run dev              # http://localhost:5000

## 3. Frontend
    cd client
    npm install
    npm run dev              # http://localhost:5173

## API
| Method | Route                  | Purpose                      |
|--------|------------------------|------------------------------|
| POST   | /api/applications      | Add application              |
| GET    | /api/applications      | List applications            |
| PUT    | /api/applications/:id  | Edit / change stage          |
| DELETE | /api/applications/:id  | Delete application           |

## Rules
- Applied date cannot be in the future (checked in the form and again by the Mongoose schema).
- `applicationId` (e.g. `JA-INF-004`) is generated by the server from an atomic per-prefix counter
  in the `counters` collection. Client-sent values are discarded.
- Status workflow: Applied → Interview/Rejected; Interview → Offer/Rejected; Offer → Accepted/Declined.
  Rejected, Accepted and Declined are final. New applications always start as Applied.
  Invalid changes return HTTP 400 with a message. The API sends `nextStatuses` with each application
  and the dropdown shows only those.
- Status history: every change is stored as {status, changedAt}; shown as a timeline on the details page (`#/applications/<id>`).
- Follow-up date = applied date + 7 days, set by the server. `isOverdue` is true when the status is still Applied
  and the follow-up day has passed (UTC).
- Duplicates: same company + job role (case-insensitive) cannot be added while an earlier one is active
  (Applied, Interview or Offer). Returns 409. A partial unique index also guards simultaneous requests.
- List filters (backend): `GET /api/applications?status=Applied&search=acme` (search = company contains, case-insensitive).
  `GET /api/applications/stats` returns the count per status shown at the top.
- Edit: company, role, job type, salary and notes only. Application ID and Applied Date are locked:
  the schema marks them immutable and the API returns 400 if an edit tries to change them.

## API response format and status codes
Every response is `{ "success": boolean, "message": string, "data": any | null }`.
- 200 OK (read, update, delete), 201 Created (add)
- 400 Bad request (validation, invalid status transition, editing a locked field, bad JSON)
- 404 Not found (unknown id or route)
- 409 Conflict (duplicate active application, deleting an Interview/Offer application, simultaneous change)
- Delete rule: only Applied or a final status (Rejected, Accepted, Declined) can be deleted. The API enforces it
  and sends `canDelete` with each application; the UI disables the Delete button and asks for confirmation.
